# Embed build

WordCraft's embed build is a WebAssembly module that a host page mounts on its own `<canvas>`
and drives through one typed JavaScript API, `EmbeddedEditor` (`wordcraft_embed.d.ts`). An
editor mounts in **view mode** (the document with the editor's own page navigation, zoom and
find); API 0.2 (release `embed-v0.2.0`) adds **edit mode**, in which every change is a tracked
change, and save, which hands the `.docx` bytes to the host ("Edit mode (API 0.2)"). Sources:
`apps/wordcraft-embed` (wasm-bindgen glue) and `crates/ui-egui/src/host/` (host bridge, view and
edit mode, marks, selection, opening files).

## Build

```sh
packaging/embed/package.sh   # dist/release/wordcraft-embed-<version>.zip and .zip.sha256
```

It needs the `wasm32-unknown-unknown` target, `wasm-bindgen` at the version in `Cargo.lock`
(`cargo install wasm-bindgen-cli --version <it> --locked`, or `WASM_BINDGEN=…`), binaryen's
`wasm-opt` at the version in `packaging/embed/tools.env` (`WASM_OPT=…` names a binary; the script
refuses any other version and runs `wasm-opt -Oz`), cargo-about at the version in
`packaging/embed/cargo-about.env`, `jq` and `python3`. The version is `apps/wordcraft-embed`'s
own, not the app's (`packaging/embed/package.sh --print-version`); release tags are
`embed-v<version>`.

The zip holds, at its root:

| File | What |
|---|---|
| `wordcraft_embed.js` | generated glue (ES module) |
| `wordcraft_embed_bg.wasm` | the editor |
| `wordcraft_embed.d.ts` | generated TypeScript declarations |
| `LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE`, `ATTRIBUTION.md` | WordCraft's licences and attribution |
| `licenses/` | the licence texts of the third-party assets compiled into the module: Inter, JetBrains Mono, Source Sans 3 and Source Serif 4 (OFL 1.1), egui's default fonts (Ubuntu Font Licence, Hack, OFL 1.1 for Noto Emoji, MIT for emoji-icon-font) and krilla's compact ICC colour profiles (CC0); plus `OFL-<family>.txt` for each craft-fonts family when built with `CRAFT_FONTS_DIR` |
| `THIRD-PARTY-LICENSES.txt` | the licence notices of the Rust crates compiled into the module (generated by cargo-about): one section per licence text with the crates that use it, the NOTICE files those crates ship, and the Rust standard library's notices from the build toolchain |
| `SHA256SUMS` | the SHA-256 of every file above |

The English word list and hyphenation patterns compiled into the module are public domain and
CC0; they need no licence text and are named in `ATTRIBUTION.md` and `NOTICE`. The UI icons are
drawn in code (WordCraft's own).

`THIRD-PARTY-LICENSES.txt` covers the embed crate's dependencies for `wasm32-unknown-unknown`
(`about.toml`, `packaging/embed/about.hbs`; no build scripts or tests), written by
`packaging/embed/third-party-licenses.sh`, which the `Embed licences` workflow also runs alone.
It fails on a crate whose licence is unknown or not in `about.toml`'s accepted list, and on a crate
whose notice still shows a placeholder such as `<copyright holders>`: give that crate a
`[<crate>.clarify]` section in `about.toml` that points at the licence file naming its holder, or,
when none exists, list it with the reason in `packaging/embed/about-placeholder-allowlist.txt`. A
clarification fetches the upstream file at the package's commit, checked against a SHA-256, so a
release needs network access and a changed upstream file fails the package until reviewed. The
standard library notices come from the running toolchain, which must be the one the embed
workflows pin (their `toolchain:` lines; `RUSTUP_TOOLCHAIN=<it>` locally).

The zip is reproducible: its bytes depend only on the toolchain and tools (the pinned Rust
toolchain, `wasm-bindgen`, `wasm-opt`, cargo-about), the commit and the dependencies locked in
`Cargo.lock`, not on the machine, user or checkout path (fixed timestamps under `TZ=UTC`,
byte-order file lists under `LC_ALL=C`, mode 644, no extra attributes or folder entries). The
module records the commit (the About text's version line) and the source path of each panic
location; the script rewrites those paths with `--remap-path-prefix` (registry and git crates to
`/cargo/registry/src` and `/cargo/git/checkouts`, the checkout to `.`) and fails if the module or
its glue still holds `CARGO_HOME`, the checkout path or the home folder.

The script sets `CARGO_ENCODED_RUSTFLAGS`, which cargo prefers over every other source of
rustflags, so it carries over the caller's `RUSTFLAGS` (or the wasm target's or `build`'s
environment variable) and refuses to build while a cargo config file on the checkout's ancestor
path or in `CARGO_HOME` sets rustflags that could apply to the wasm build, because those would be
replaced without a word: `[build]` (also `build.rustflags`), `[target.wasm32-unknown-unknown]`
(also dotted or quoted) and any `[target.'cfg(...)']` section (a cfg expression may match wasm32
and the script cannot evaluate it). Rustflags for another target triple, such as a host linker
under `[target.x86_64-unknown-linux-gnu]`, never reach this build and are allowed; pass flags
meant for the wasm build in `RUSTFLAGS`. `packaging/embed/rustflags-guard.sh` holds the check and
`packaging/embed/test-rustflags-guard.sh` tests it.

### Reproducing a release

To rebuild a release's zip and compare it with the published `.zip.sha256`:

1. Check out the tag cleanly (`git clone`, or `git checkout embed-v<version>` in a tree with no
   changes). The commit is compiled into the module's About text, so a build from another commit,
   even with identical sources, differs.
2. Use the Rust toolchain the workflows pin (their `toolchain:` lines): `RUSTUP_TOOLCHAIN=1.95.0`,
   with the `wasm32-unknown-unknown` target.
3. Install `wasm-bindgen-cli` at the version `Cargo.lock` locks for `wasm-bindgen`
   (`awk '/^name = "wasm-bindgen"$/ { getline; print; exit }' Cargo.lock`), with `--locked`.
4. Install binaryen at the version in `packaging/embed/tools.env` (123); its SHA-256 for the Linux
   x86_64 release is there too (`packaging/embed/install-binaryen.sh` does it on that platform).
   `package.sh` refuses another `wasm-opt`.
5. Install cargo-about at the version in `packaging/embed/cargo-about.env`
   (`packaging/embed/install-cargo-about.sh`), and have `jq` and `python3`.
6. Run `packaging/embed/package.sh`, then compare `dist/release/wordcraft-embed-<version>.zip.sha256`
   with the release's file, and run `packaging/embed/verify-zip.sh` on your zip.

Honest status: equality has been checked between builds on one machine (macOS) and at different
checkout paths. It has not yet been checked between macOS and the Linux runner that builds the
release, so a build on another platform may differ in bytes (compare the files inside the zip:
`unzip -p <zip> SHA256SUMS` lists each file's hash) until someone has compared the two.

### CI and releases

`Embed CI` (`.github/workflows/embed-ci.yml`) runs on pull requests into `*-embed` branches and on
pushes to them: actionlint, shellcheck, `packaging/embed/test-verify-zip.sh` (crafted zips the
verifier must refuse), `packaging/embed/test-rustflags-guard.sh` (the rustflags check above),
`cargo --locked xtask ci` (which ends with `cargo xtask embed`: the host
tests without default features, the configuration the module ships, and clippy for
`wordcraft-embed` on wasm32; every cargo call in it is `--locked`) and a dry run of the package.
A tag `embed-v<version>` runs `Embed release`: first a seconds-long job that fails a tag that does
not match `apps/wordcraft-embed`'s version, then the same gates and the build (uncached, so no
earlier run's outputs reach the release), a check of the zip with
`packaging/embed/verify-zip.sh`, then a GitHub release holding
`wordcraft-embed-<version>.zip` and `wordcraft-embed-<version>.zip.sha256`. The release job alone
holds the write token and the right to attest.

`verify-zip.sh` extracts nothing. It requires the `.sha256` to be one line naming this zip with
its hash, the entry names to be exactly the files listed in "Build" (plain relative names: no
absolute path, `..`, backslash or folder entry, at most 100 characters, no two differing only in
case) and `SHA256SUMS` to list each of them once, and it hashes every entry streamed out of the
zip. A host can run it on a download.

The release job attests the zip and its `.sha256` file with GitHub artifact attestation (signed
SLSA build provenance, `actions/attest-build-provenance`). The checksum only shows that a file is
consistent with itself; the attestation shows which repository, workflow and tag built it. A host
verifies a downloaded zip before trusting it, with the GitHub CLI:

```sh
gh attestation verify wordcraft-embed-<version>.zip --repo rsysapp/wordcraft
```

The command fails for a file that was not built by this repository's release workflow.

## API

```ts
import init, { EmbeddedEditor } from './wordcraft_embed.js';
await init({ module_or_path: './wordcraft_embed_bg.wasm' });
const editor = await EmbeddedEditor.mount(canvas, { mode: 'view', theme: { dark: false, accent: '#0f766e', accentContent: '#ffffff' } });
editor.setListener((event) => { /* see EditorEvent below */ });
editor.open(bytes, 'agreement.docx');
editor.jumpTo({ kind: 'text', text: 'Clause 5', page: null, occurrence: 0 });
editor.setMarks([{ id: 'n1', text: 'Clause 5', page: null, color: '#ffd60080' }]);
// API 0.2: edit, then save; the bytes arrive in a `saveRequested` event.
editor.setMode({
    mode: 'edit',
    author: { id: 'u-1', name: 'A. Person' },
    revisionDate: '2026-10-10T08:00:00Z',
    permissions: { acceptRejectChanges: true, organizePages: false, fillForms: false, redact: false, stamps: false, drawing: false },
});
editor.requestSave();
editor.setMode({ mode: 'view' });
editor.destroy();
```

`EmbeddedEditor`'s methods are `static mount(canvas, options)`, `open(bytes, fileName)`,
`jumpTo(target)`, `setMarks(marks)`, `setTheme(theme)`, `setListener(listener)`, `destroy()` and,
from API 0.2, `setMode(request: ModeRequest)`, `requestSave()` and `applyRedactions()`. The types,
as `wordcraft_embed.d.ts` declares them (the package script fails if a declaration is missing):

```ts
export interface MountOptions {
    mode: 'view';
    theme: Theme;
}

export interface Theme {
    dark: boolean;
    accent: string;
    accentContent: string;
}

export type JumpTarget =
    | { kind: 'page'; page: number }
    | { kind: 'text'; text: string; page: number | null; occurrence: number };

export interface Mark {
    id: string;
    text: string;
    page: number | null;
    color: string;
}

export interface EditorAuthor {
    id: string;
    name: string;
}

export interface EditorPermissions {
    acceptRejectChanges: boolean;
    organizePages: boolean;
    fillForms: boolean;
    redact: boolean;
    stamps: boolean;
    drawing: boolean;
    fullEditing?: boolean;
}

export type ModeRequest =
    | { mode: 'view' }
    | { mode: 'edit'; author: EditorAuthor; revisionDate: string; permissions: EditorPermissions };

export type EditorEvent =
    | { type: 'opened'; pages: number }
    | { type: 'openFailed'; message: string }
    | { type: 'pageChanged'; page: number }
    | { type: 'selection'; text: string; copyText: string; page: number | null; x: number; y: number }
    | { type: 'selectionCleared' }
    | { type: 'markActivated'; id: string }
    | { type: 'jumpNotFound'; target: JumpTarget }
    | { type: 'modeChanged'; mode: 'view' | 'edit' }
    | { type: 'dirtyChanged'; dirty: boolean }
    | { type: 'saveRequested'; bytes: Uint8Array; fileName: string }
    | { type: 'saveFailed'; message: string }
    | { type: 'commentRequested'; text: string; copyText: string; page: number | null; x: number; y: number }
    | { type: 'redactionsPending'; marks: number }
    | { type: 'editRefused'; code: EditRefusalCode };

export type EditRefusalCode =
    | 'command_not_allowed'
    | 'decision_not_allowed'
    | 'paragraph_break_not_supported'
    | 'character_not_allowed'
    | 'outside_editable_story'
    | 'invalid_edit_session'
    | 'unknown_command'
    | 'invalid_parameters'
    | 'not_available'
    | 'document_protected'
    | 'command_failed';
```

`MountOptions.mode` is always `'view'`: an editor mounts in view mode, needing no author, and
`setMode` switches it. `EditorPermissions` is the API's shared shape; this editor reads
`acceptRejectChanges` and `fullEditing` only. `redactionsPending` belongs to the other editor of the API: this one
never sends it, and its `applyRedactions()` does nothing.

## Edit mode (API 0.2)

`setMode({ mode: 'edit', author, revisionDate, permissions })` switches the open document to edit
mode on the next frame; `modeChanged` answers with the mode now in force. With no document open
(none opened yet, or the last open answered `openFailed`) it answers `modeChanged` with `view`. A
selection reported in view mode is cleared first (`selectionCleared`, then `modeChanged`).
`setMode({ mode: 'view' })` leaves edit mode and keeps the edits on screen; the host calls `open`
again to discard them. A malformed request (an unknown mode, a missing author, a blank author name
or one over 255 characters, a `revisionDate` that is not ISO 8601 UTC on a calendar day, a
permission that is missing, not a boolean, or not one the API names; `fullEditing` alone may be
left out) throws a `TypeError`
and queues nothing. An unknown permission is refused, never ignored (a restriction the editor cannot
read must not become a tool it offers); fields of `author` it does not read are ignored.

Every change is a tracked change by `author.name`, dated `revisionDate` stored to the second
(`2026-10-10T08:00:00.123Z` is `2026-10-10T08:00:00Z`); tracking is forced on and is on in the saved
file. **One author and one date per save**: while the document has unsaved changes, `setMode` with
another `revisionDate`, or another author (id or name), is refused with `editRefused`
`invalid_edit_session`, then `modeChanged` with the mode still in force; on a clean document it
starts a new session.

Only typing, deleting, line breaks (Shift+Enter), tab characters, cut, plain paste, undo and redo
run, and, with `acceptRejectChanges`, accepting and rejecting tracked changes; formatting, styles,
tables, pictures, fields, find-and-replace, list levels, indents and restricting editing do not
(each would be an untracked change). New paragraphs are refused for now ("Known limitation" below).
**Full editing.** With `fullEditing: true` the view bar and edit strip give way to the
application's full ribbon (Home, Insert, Layout, Review and the rest), and every command runs:
formatting, styles, tables, pictures, new paragraphs, rich paste, Tab and Shift+Tab as in the
application, and accepting and rejecting tracked changes. Typed and deleted text is still tracked
under `author.name` and `revisionDate`; formatting changes are not tracked. The file stays the
host's: Backstage, the File tab and the application's own open, save and export commands are
refused (`command_not_allowed`), and a save still answers with `saveRequested`. Missing or `false`
leaves edit mode exactly as described below.

The edit strip in the view bar offers Undo, Redo, Previous change, Next change and, when allowed,
Accept, Reject, Accept all and Reject all. **Headers and footers** are entered by double-clicking
them, and the part entered is the one the clicked page shows, as Word renders it: the first-page
part on a title page, the even part on even pages when odd and even differ (none, so nothing to
enter, when there is no even part), or a part inherited from an earlier section, which is shared:
the strip then says "Header (shared with sections N–M)". Making a new header or footer is refused.

- **Refusals.** An action the editor refuses (a key, a paste, a strip button) changes nothing and
  sends `editRefused` with its code, once per action; the codes are listed under "Edit mode
  (engine)" below. The editor also shows its own short notice. A search or move that finds nothing
  is no refusal and sends nothing, and Shift+Tab does nothing and says nothing.
- **A command that changes nothing leaves no trace**: Accept with nothing to accept, or an empty
  paste, adds no revision record and no undo step, keeps the redo history, and makes the document no
  dirtier.
- **Dirty.** `dirtyChanged` is `true` once the document differs from what was opened and `false`
  when it no longer does (undoing back to the opened document), at most once a frame and only on a
  change. It compares the document's content, not the undo depth, so running out of undo leaves it
  dirty. **Saving never clears dirty; only `opened` does**: the next `opened` starts clean without a
  `dirtyChanged`, so a host resets its own dirty state on `opened`, and a host that keeps a save
  opens the saved bytes again.
- **Save.** `requestSave()`, or Ctrl/⌘+S in edit mode, answers `saveRequested` with the `.docx`
  bytes in a new `Uint8Array` the host owns (a copy outside the module's memory) and `fileName`, the
  name the document was opened under, verbatim (`LEASE.DOCX` stays `LEASE.DOCX`). The bytes are
  always a Word `.docx` package, also for a file opened as `.docm` or `.dotx`. **Saves are answered
  when requested**: each from the document and mode at its own request, before a later command of
  the same frame (an `open`, a `setMode`), so a save asked in view mode answers `saveFailed` even
  when a later one in the same frame, after `setMode`, answers `saveRequested`. Two requests in one
  frame, for the same document in the same mode with nothing changed in between, answer once. Every
  other save gets exactly one answer. In view mode `requestSave()` answers `saveFailed` ("Nothing to
  save: the document is open for viewing only.") and Ctrl/⌘+S sends nothing; a document that cannot
  be written answers `saveFailed` ("The document could not be written."), and so does a save whose
  bytes the page cannot take, when allocating their array fails ("The document could not be handed
  to the page."); the editor keeps working. Saving never leaves edit mode and never downloads: the
  host decides what a save becomes. The size of a save is not limited here.
- **Comments.** The editor's comment command (New Comment and its shortcut) never writes into the
  file: with text selected it sends `commentRequested` with the fields and meaning of `selection`;
  with nothing to quote (a collapsed caret, or only tracked-deleted or hidden text) it sends
  nothing.
- **Selection, marks and jumps.** `selection` and `selectionCleared` are not sent in edit mode, and
  leaving it reports nothing about a selection made while editing until the person changes it. Host
  marks are hidden while editing and shown again in view mode; `setMarks` while editing replaces
  them for then. Jumps work as in view mode, and `pageChanged` follows the view, also when typing
  moves the caret onto another page.
- **Opening.** `open` always starts in view mode. Of the events one open sends, each only when it
  applies, the order is `modeChanged` with `view` (when it was editing), `selectionCleared`, the
  waiting jump's `jumpNotFound`, then `opened` or `openFailed`. A file over the open limit is an
  open like any other, so it ends edit mode too.
- **Keyboard.** Tab types a tab character, tracked, and nothing else: it never moves between table
  cells, adds a row, changes a list level or indents. Shift+Tab does nothing. In edit mode the host
  lets Tab and Shift+Tab reach the canvas, except right after Escape: Escape then Tab or Shift+Tab
  moves focus out ("The host page's part"). Escape itself reaches the editor harmlessly (in a header
  or footer it leaves it). Edit mode claims the IME, so composed and on-screen typing arrive; view
  mode never does.

## Behaviour a host page relies on

- Call the module's default export (`init`) before `EmbeddedEditor.mount`. `mount` applies the
  theme before the first frame and resolves after it.
- Set the listener before `open`: events raised while there is no listener are dropped. Events
  arrive after the frame that produced them, so a listener may call the editor, `destroy()`
  included. `opened` is followed by `pageChanged` for the first page, and no `pageChanged` comes
  before the first `opened`.
- `open` takes `.docx`, `.docm` and `.dotx` files. It replaces the document and clears the marks.
  Of the events one successful open sends, each only when it applies, the order is:
  `selectionCleared` (a selection it reported), then the waiting jump's `jumpNotFound`, then
  `opened`, then `pageChanged`; in edit mode `modeChanged` with `view` comes first. A file that
  cannot be shown answers `openFailed` with a plain one-sentence message (unsupported type, empty,
  too large, password-protected, damaged) and leaves the open document, its marks and any waiting
  jump as they were, though not editable: edit mode waits for the next document that opens. There
  is never a password prompt.
- **Matching** (jumps and marks): whitespace runs are one space; case, Unicode compatibility forms
  (NFKC), curly quotes and the dashes U+2010–2015 and U+2212 are folded. Text in tracked deletions
  and hidden text is not matched. A match may span lines, never paragraphs. A mark shows its first
  match (on its page when given); marks not found are skipped. Pages are layout pages, 1-based.
- **Jumps**: a found jump moves the view and reports `pageChanged`; one that finds nothing answers
  `jumpNotFound` with the target echoed. A newer `jumpTo` replaces one still waiting, which is not
  answered; opening a document answers a waiting jump with `jumpNotFound` before `opened`.
- **Selection**: sent each time a selection settles (pointer released, or a keyboard selection
  changed), not on every frame, and again when a new press and release ends on the same text as the
  selection reported before (the host hides its toolbar on any input); `x`, `y` are CSS pixels from the canvas's top-left at the selection's end. `text` has
  whitespace collapsed; `copyText` keeps line breaks; both leave out tracked deletions and hidden
  text. Selections the editor makes itself (a jump, find, its page buttons) are never reported.
  When the editor moves the view that way, or opens a document, a selection it reported is answered
  with `selectionCleared`; a jump that finds nothing leaves it.
- **Marks** are painted above the page and below the selection. Clicking inside one sends
  `markActivated`; where marks overlap, the topmost (last in the array) wins; a click that ends a
  text-selection drag activates nothing.
- Malformed arguments (wrong shape, non-integer or negative numbers, NaN or infinities, bad
  colours, `open` with anything but a `Uint8Array` and a string, a listener that is not a function)
  throw a `TypeError` and queue nothing; `mount` rejects with a `TypeError` for anything but an
  `HTMLCanvasElement` and `mode: 'view'` with a valid theme. Show what they throw as text: the
  messages echo the strings the host sent.
- `destroy()` stops the runner and frees the canvas. Later calls do nothing and deliver nothing
  (malformed arguments still throw); a second `destroy()` does nothing. `free()` (or
  `[Symbol.dispose]()`, or garbage collection) destroys the editor too. After `free()` the object
  is gone: wasm-bindgen throws on any later call, `destroy()` included.
- Each `mount` installs eframe's panic hook; mounting and destroying repeatedly in one page chains
  hooks, one per mount. Nothing is stored in the host page's storage.

## The host page's part

- **Keyboard:** eframe's web backend keeps Tab inside the canvas. Wrap the canvas in an element
  with a capture-phase `keydown` listener that stops Tab and Shift+Tab and moves focus to the next
  or previous focusable element. Everything else reaches the editor. In edit mode, Tab types a tab
  character, so the wrapper lets Tab and Shift+Tab through unless the key before it was Escape
  (Escape arms the next key; any other key disarms it; Escape itself still reaches the editor), and
  the host shows this way out beside the editor while it edits.
- **Toolbar:** hide the host's selection toolbar on `opened` and `openFailed`, and on any pointer,
  wheel or key input in the canvas's wrapper, since a reported selection's position goes stale once
  the view moves; Tab and Shift+Tab are exempt (the wrapper consumes them to move focus, and while
  the toolbar is open Tab moves to it first).
- **Timeouts:** put a timeout on `open` and on `mount` (see "Crashes").
- Size the canvas with CSS; the editor follows it.
- Phones and screen readers are not supported in this version.

## Limits

- `setMarks` keeps the first 2,000 marks (`MAX_MARKS`) and ignores the rest.
- Passages are at most 256 KiB of UTF-8 as sent (`MAX_RAW_PASSAGE_BYTES`, checked before anything
  is folded) and 10,000 characters once folded (`MAX_NEEDLE_CHARS`): a longer mark is skipped, a
  longer text jump answers `jumpNotFound`.
- Page numbers and occurrences of any size are accepted when they are whole numbers (including the
  exponent form `JSON.stringify` writes from 1e21); values above 4294967295 saturate to it, so they
  are out of range for any document: the jump answers `jumpNotFound` with 4294967295 echoed, the
  mark is skipped.
- `open` takes files of at most 100 MB (`MAX_OPEN_BYTES`, 100 MiB). A larger one is answered, in
  order, `openFailed` ("This file is too large or complex to be shown here.") without its bytes ever
  being copied into the module, and leaves the open document unchanged. The size is judged before
  anything else, so a file over the limit gets this answer whatever its name or type (a large PDF
  too, not the unsupported-type message). An empty array, which is
  also how a detached or transferred buffer reads, is answered `openFailed` without being touched.
- Inside a Word package the embed build reads at most 64 MiB per part, 192 MiB in all and 2,000,000
  XML elements across the package (below the desktop app's limits, because a failed allocation aborts a
  WebAssembly module and its memory never shrinks), with elements nested at most 64 deep (the desktop
  allows 256). The reader recurses once per level and a stack overflow traps the module; measured
  in Chromium, the deepest path uses about 2 KiB of the 1 MiB WebAssembly stack per level, so 64
  levels stay near 140 KiB. A file beyond any of these limits answers the same `openFailed` message
  as an oversized one.
- Matching cost: the document's text index is built once per document and shared by jumps and
  marks. All marks are looked for in one pass over the document with an automaton built from at
  most 64 bytes of each passage (each candidate is then checked against the whole passage), and
  that work, like placing the marks' rectangles, stops after a time budget per frame and goes on in
  the next, so a long list on a long document never stalls a frame. The budget is also looked at
  between the passages compared at one place, so marks crafted to share a long opening with the
  document's text take many frames, not one long one. Marks show their first match only.
- The command and event queues are unbounded: the host page is trusted not to flood them.

## Crashes

A Rust panic aborts the WebAssembly module: there is no unwinding on wasm32. A stack overflow or a
failed allocation traps it the same way. After a trap the editor sends nothing more and later calls
may throw. The host therefore treats "no `opened` or `openFailed` within its timeout after `open`",
or a call that throws, as a failure: it shows its own failure panel and discards the whole module
instance, never mounting on it again.

A trap leaves the instance's memory as it was: locks held (the font caches, for one), the stack
pointer not restored. And `init` returns the same cached instance. A new editor mounted on it can
therefore crash at once or hang until the host's timeout. So after a failure the host:

1. calls `destroy()` on the failed editor inside a `try`, since after a trap it may throw;
2. drops every reference to that editor and to the module it came from;
3. for the next mount, loads a fresh instance: a new `import()` of the glue under a new URL (its own
   module record, for example `wordcraft_embed.js?attempt=2`), then that glue's `init`, which makes
   a new WebAssembly instance with its own memory. The compiled `WebAssembly.Module` may be reused
   (pass it to `init` as `module_or_path`); only the instance must be new. A recreated iframe or
   worker that loads the glue is a fresh instance too.

`destroy()` throws nothing by itself. It can throw only after a trap, or after `free()` (wasm-bindgen
refuses any call on a freed object). Both are cases where the host's `try` is needed anyway.

The host also puts a timeout on `mount`: `mount` resolves after the first frame, which a canvas that
never paints (in a hidden tab, say) or a failed start does not produce. On a `mount` timeout, keep
the promise and `destroy` the editor if it resolves late.

eframe paints on animation frames, which a browser does not run in a hidden or background tab. There
`mount`'s first frame, and the `opened` or `openFailed` that answers an `open`, wait until the tab
is visible again. A host therefore pauses its `open` and `mount` timeouts while `document.hidden`
is true (resuming them on `visibilitychange`), or a document opened in a background tab is taken
for a crash.

- `destroy()` may be called from any handler, including one eframe triggers inside a frame (its
  text agent's `focusin`/`focusout`, or a `blur`): it stops everything at once and defers only the
  runner's teardown to a microtask, after the frame has returned. So calling it from a focus or blur
  handler is safe.
- Well-formed calls after `destroy()` are no-ops: they queue and deliver nothing. Malformed
  arguments still throw their `TypeError` (see "Behaviour a host page relies on"), so a host that
  validates nothing itself sees the same errors before and after `destroy()`.
- Do not call `free()` from host code that runs inside an editor call: a getter, a Proxy or a
  `toJSON` passed in as an argument. wasm-bindgen then leaves the editor alive but unreachable (the
  call still holds it). Call `destroy()` instead, or `free()` afterwards.
- `open` requires a `Uint8Array` from the host page's own realm (not from another frame or window).
  A Proxy around one is not supported: its copy may leave zeros.

## View mode

No title bar, ribbon, Backstage, status bar, side panes, dialogs, context menus, file open, save,
download or print. The document area keeps the file's own markup, read-only: tracked changes and
Word comment balloons beside the page. Every edit is refused in two places: `Session::run` runs
only `wordcraft_engine::view_only::COMMANDS`, and `WordApp::run` refuses UI commands, saving and
downloads, whatever the keyboard or pointer does. Ctrl/⌘+C copies the selection as the `selection`
event's `copyText` reports it (no tracked deletions or hidden text). Links inside the document are
not followed.

## Edit mode (engine)

How the engine and the host bridge implement API 0.2's edit mode ("Edit mode (API 0.2)" above is
what a host sees). `Session::begin_edit(author, revisionDate, rules)` is the only way into an
edit session. It refuses a blank author or a date that is not UTC whole seconds on a calendar day
(`2026-10-10T08:00:00Z`; `2026-02-31T08:00:00Z` is refused), forces tracking on and clears undo and
redo, so neither reaches past the session's start. Starting again with another author, other rules
or another date starts a new session; starting again with the same ones keeps the session running.
The engine does not keep one date per save by itself: the host bridge refuses another date while
the document has unsaved changes (below). Only `begin_edit` names the session's author: `Session::author` is
put back to it before every command of the session, whatever wrote it since. In a session, `Session::run` runs only `wordcraft_engine::edit_mode`'s
allow-list: typing, deleting, line breaks, nonbreaking spaces and hyphens, Tab as a tracked tab
character, cut, paste as plain text, undo, redo, moving between changes, and going into the header or footer
a page shows and back (making a new one is refused); accepting and rejecting only with the
permission to decide. The part entered is the one the page shows, as Word renders it: the
first-page part on a section's title page, the even part on even pages when odd and even differ
(none, and so nothing to enter, when there is no even part), and a part inherited from an earlier
section when the page's own section has none. Editing an
inherited part edits every section that shows it (Word's "link to previous"). A command that
changes nothing (Accept with nothing to accept, an empty paste) leaves no revision record, no undo
step and the content version as it was. Every change is a tracked change by the session's author,
dated with its date. A change counts as the session's own only when the session made its revision
record, whatever a file revision's author or date. Deleting the session's own insertion removes
it, deleting anything else marks it deleted, and accepting leaves the session's own changes
tracked. Only the main text, headers, footers, footnotes and endnotes are edited; comments and
text boxes stay as the file has them.

A refusal is `CmdError::Editing`, with a stable code in `edit_mode::Refusal::code`, also left in
`Session::refusal` and `Session::status`, for the host to map to its own message. In an edit
session every error `Session::run` answers is one, so the host never parses an error's text. A
search or a move that finds nothing (`edit.find`, `edit.findNext`, `edit.findPrevious`,
`edit.goto`, `review.nextChange`, `review.previousChange`) refuses no edit and is no refusal:

| Code | Refused |
|---|---|
| `command_not_allowed` | a command off the allow-list |
| `decision_not_allowed` | accepting, rejecting, or redoing a decision, without the permission |
| `paragraph_break_not_supported` | Enter, and typed or pasted text with a paragraph break |
| `character_not_allowed` | typed or pasted page or column breaks, other control characters, and directional formatting characters |
| `outside_editable_story` | an edit with the selection in a comment or a text box |
| `invalid_edit_session` | `begin_edit` without an author or a valid date |
| `unknown_command` | a command id nothing registers |
| `invalid_parameters` | missing or malformed parameters |
| `not_available` | a command that does not apply where the selection is (Cut with nothing selected) |
| `document_protected` | a change the document's own Restrict Editing setting refuses |
| `command_failed` | a command that failed; the document is as it was |

The host bridge (`crates/ui-egui/src/host/edit.rs`) begins the engine's session once per entry into
edit mode: `setMode` with the author, date (to the second) and rules already running keeps the
session. A malformed request is refused before it is queued; a request queued with a date the
calendar lacks, or with no document open (none yet, or the last open failed), answers `modeChanged`
with `view`. Every open, a refused one included, ends edit mode first.

- **Refusals.** Each refused action (a key, a paste, a strip button) sends `editRefused` with its code
  once, and the editor shows the code's words over the document, at the view's top, or at its bottom
  when the caret's line is under the top, until the document changes or the caret moves. Shift+Tab
  does nothing and says nothing.
- **One date and one author per save.** While the document has unsaved changes, `setMode` with
  another `revisionDate`, or another author (id or name), is refused: `editRefused` with
  `invalid_edit_session`, then `modeChanged` with the mode still in force. The same date and author
  continue the work; on a clean document another date or author starts a new session.
- **Dirty: saving never clears it; only `opened` does.** `dirtyChanged` compares the document's
  content version (`Session::content_version`) with the one it had when it opened, so undoing back
  to the opened document is clean and running out of undo is not. A save leaves dirty as it is (the
  contract: saving never clears dirty). The next `opened` starts clean, without a `dirtyChanged`, so
  a host resets its own dirty state on `opened`; a host that keeps a saved file opens it again.
- **Saves** are answered when asked: `requestSave` and Ctrl/Cmd+S serialise the document then, before
  a later command of the same frame (an open, a mode change), each from the state at its own
  request: a save asked in view mode answers `saveFailed` even when a later one in the same frame,
  after `setMode`, answers `saveRequested`. Two requests in one frame, for the same document in the
  same mode with nothing changed in between, answer once.
- **The edit strip** follows the zoom controls, and wraps onto a second row of the view bar when the
  bar is too narrow for it and the find controls. While the caret is in a header or footer several
  sections show, it says so ("Header (shared with sections 1–3)").
- **Headers and footers** are entered by double-clicking them, on the page clicked
  (`insert.editHeader` and `insert.editFooter` take `{ "page": <0-based index> }`, else the caret's
  page), and left with Escape or a double-click in the text.

**Known limitation: new paragraphs.** API 0.2 lists new paragraphs among edit mode's edits, but
Enter is not available in edit mode yet, and pasted text with paragraph breaks is refused. The
Word writer does not yet record an inserted paragraph mark as a tracked change, so a new paragraph
would be saved untracked. Enter returns once it does; until then it is refused with
`paragraph_break_not_supported` (`editRefused`). Line breaks (Shift+Enter) work.

## Branding

The embed build is a modified version of WordCraft: it carries none of the ArtCraft logo images
and shows no ArtCraft names or links (`docs/brand/LICENSE-brand.txt`). WordCraft draws no logo
image; its community links and About wording sit behind the `brand` feature of
`wordcraft-ui-egui`, on by default and off in the embed build, and the package script fails if
they are in the module. Build `wordcraft-embed` with `-p wordcraft-embed` alone: building it
together with the apps (`--workspace`, or `-p wordcraft-web`) unifies `brand` back on.

Three ArtCraft names remain in the binary, none of which view mode can show. The package script
counts each exactly and fails on any other occurrence of the name, in any case:

| Leftover | Source | Why view mode never shows it |
|---|---|---|
| the About dialog's copyright line | `crates/ui-egui/src/dialogs.rs` | view mode has no dialogs |
| the sample document's link `https://getartcraft.com/` | `crates/engine/src/sample.rs` | only `file.new` with the `sample` template loads it; view mode refuses that command, and the host opens only its own files |
| the word `artcraft` in the spelling dictionary | `crates/proof/src/lib.rs` | a dictionary word is shown only as a spelling suggestion, in the context menu view mode does not have |

`NOTICE` in the zip says in plain text that the build is based on WordCraft by the ArtCraft team.
